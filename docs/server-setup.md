# 電柵アラート (HPX-F) の組み込み手順

> 2026-11-08 に機器名を HPX-A から HPX-F (Fence = 電柵) に変えました。あわせて BLE の広告も変えたので、HPX-F のファームは `HPX_F_v1_04` 以降、HPX-Core は v1.23 以降を組み合わせてください (古い HPX_Alert v1.03 以前とは受け渡しできません)。

StaFIX フェンスアラートの LED の点滅を HPX-F が数え、BLE で HPX-Core に送り、さくらのサーバーがメールで知らせます。

```
フェンスアラートの LED ─(光)→ 光センサ → HPX-F (XIAO nRF52840)
   ─(BLE 約10m)→ HPX-Core v1.23 ─(Wi-Fi・HTTPS)→ さくら receive.php → ble.csv に保存
                                                               └→ hpx_alert.php → メール
                                          CRON か外部の定期実行 → hpx_cron.php → ハブが止まったらメール
```

## 1. HPX-F を作る

最新のファームは `HPX_F_v1_04/HPX_F_v1_04.ino` です (2026-11-08、名前の変更。中身は 2026-11-02 の v1.03 と同じ)。光センサをアナログで読み、日光の影響を受けにくくしました。`HPX_Alert_v1_00/` (中身は v1.01) は古い配線用です。

部品: Seeed XIAO nRF52840 (通常版)、単3リチウム電池 ×2 か CR123A (3V3 ピンへ直結)、フォトトランジスタ (例 TPS601A、PT204-6B)、抵抗 10kΩ。

**配線 (v1.02)**

```
XIAO D1 ── 抵抗 10kΩ ── XIAO D0 ── フォトトランジスタのコレクタ
                                    フォトトランジスタのエミッタ ── XIAO GND
```

- D1 は、光を読む一瞬 (20ミリ秒ごと) だけ電源を入れるためのピンです。明るい間ずっと電流が流れないので、電池が減りません。
- v1.01 の配線 (コレクタ→D0、エミッタ→GND、内蔵プルアップ) のままでは動きません。D1 と抵抗を足してください。
- フォトトランジスタを警報器の赤いカバーに向けて貼り、**赤いカバーごと**黒いキャップ (黒い熱収縮チューブ、自己融着テープ、3Dプリントなど) で覆います。赤いカバーは光を広げる導光板なので、カバーのどこかに日光が当たるとセンサまで届きます。
- アース無しの警報器は柵線に掛けて使うので、中の回路はパルスのたびに数千Vになります。警報器の回路と XIAO を電線でつながないでください (フォトカプラで LED の電流を取る旧方式Bもやめました)。

**仕組み**
- 20ミリ秒ごとに光の量 (0=暗い〜4095=明るい) を読み、ここ数秒の平均を「背景」として覚えます。
- 背景より 120 以上急に明るくなり、1秒以内に戻ったら点滅1回と数えます。日の出や雲のようなゆっくりした変化は背景として差し引かれます。
- 1秒より長く明るいままなら、日が差したとみなして背景を合わせ直します。
- 背景より暗くなった (葉や雲の影) 直後1.5秒の間に明るくなったのは、影が抜けただけとみなして数えません。

**表示LED (XIAO の内蔵LED)**
- 起動時: 緑が1秒
- 点滅を1回数えるたび: 赤が一瞬 (約20ミリ秒)。設置したとき、センサが点滅を拾えているかをその場で確かめられます
- センサが明るすぎて点滅が見えない (飽和) とき: 5秒ごとに青が一瞬
- 正常なときは光りません。`USE_INDICATOR` を `false` にすると全部消えます
- 遮光キャップの外から見えるよう、ケースに窓を開けるか、XIAO を外から見える位置に置いてください

**書き込みと調整**
1. Arduino IDE でボード「Seeed XIAO nRF52840」を選び、`HPX_F_v1_04.ino` を書き込みます。
2. シリアルモニター (115200) を開き、警報器の LED が点滅するたびに `blink width=…ms peak=…` と出ることを確かめます。
3. 晴れた日の屋外でも、遮光キャップを付けた状態で同じように試してください。
4. 合わないときの直し方:
   - `peak` が 200 に届かない → 抵抗を 22k〜47kΩ に上げる
   - 晴れた日に青が光る (明るすぎる) → 抵抗を 4.7kΩ に下げるか、遮光を見直す
   - 点滅しているのに `blink` が出ないことがある → 点滅が短すぎる可能性。`SAMPLE_MS` を 10 に下げる (電池は少し減る)
   - 光の様子を見たいとき → `DEBUG_PLOT` を 1 にして書き込み、Arduino IDE のシリアルプロッタで `light` と `bg` のグラフを見る

判定 (ファーム先頭の定数で変えられます):
- 60秒の間に3回以上点滅したら「電圧低下」
- 最後の点滅から120秒たったら「正常」
- センサが10秒以上明るすぎる (飽和) と状態2。ハブ・サーバー・メールでは従来どおり「常時点灯 (遮光・配線を確認)」と出ます
- 警報器 (StaFIX) は柵につないでいないときやパルスが来ないときにも点滅するので、電牧器の停止や手前の断線も「電圧低下」として知らせます。ただし警報器の CR2032 が切れると LED が光らず「正常」に見えるので、電池は定期的に交換してください

電池の目安 (概算、実測ではありません): 平均 30〜45µA。単3リチウム2本で計算上は数年、CR123A (約1,400mAh) で3.5〜5年ほど。

## 2. HPX-Core を v1.12 にする

1. `HPX_Core_v1_12.ino` を、v1.11 と同じ設定 (ESP32 Dev Module、Minimal SPIFFS) で書き込む。HTTPS OTA でも更新できます (FW_BUILD は 112)
2. 管理画面「動作設定」で **常時稼働 (商用電源)** を選び、記録の間隔を **15分** にする
3. 「温湿度計の登録」→「周辺の温湿度計を探す」で `[電柵アラート]` と出たものに名前 (例「電柵」) を付けて登録する
4. 「BLE温湿度計の記録」で、電柵の状態が記録されることを確認する

v1.11 で溜めた記録はそのまま引き継がれます。

## 3. さくらのサーバー

1. `config.php` に足した項目を設定する (トークンと保存先は今までの値のまま)
   - `$HPX_MAIL_TO`: 通知を受け取るアドレス (複数なら `,` 区切り)
   - メールは Gmail のアカウントから送る (さくらからの直接送信は届いたり届かなかったりしたので使わない)
     - Google アカウントで2段階認証をオンにし、https://myaccount.google.com/apppasswords で16文字のアプリパスワードを作る
     - `$HPX_MAIL_FROM` と `$HPX_SMTP_USER` に Gmail のアドレス、`$HPX_SMTP_PASS` にアプリパスワードを入れる
2. `receive.php`、`hpx_alert.php`、`hpx_cron.php` を、今の `receive.php` と同じフォルダに置く
3. hpx_cron.php を15分ごとに実行する
   - スタンダード以上のプラン: コントロールパネル「スクリプト」→「CRON設定」で
     `/usr/local/bin/php /home/<アカウント名>/www/hpx/hpx_cron.php` (パスは置いた場所に合わせる)
   - ライトプラン (CRON が無い): `config.php` の `$HPX_CRON_TOKEN` に英数字20文字以上を入れ、
     外部の定期実行サービス (cron-job.org など) から15分ごとに
     `https://<ドメイン>/hpx/hpx_cron.php?k=<$HPX_CRON_TOKEN の値>` を呼ぶ。ブラウザで開いて `ok` と出れば設定できています
4. 送信の結果は、機器ごとのデータフォルダの `mail.log` に残ります

5. 閲覧ページ `sensor.php` (と `dashboard.php`) も同じフォルダに置き、`config.php` の `$HPX_VIEW_PASSWORD` に8文字以上のパスワードを入れる。
   `https://<ドメイン>/hpx/sensor.php` を開くとセンサページが出ます (5分ごとに自動で更新。ログインは30日保持)。
   - 上の機器名のボタンで機器 (ハブ) を切り替え。機器ごとに最終受信日時、ファームウェア、電池電圧 (ハブが送る場合)、Wi-Fi の電波を表示
   - 温湿度計・重量・電柵アラートの表と、温度・湿度・重量のグラフ (それぞれ 1日/3日/7日/30日/全期間。初めは3日)
   - 重量センサは、表の下の「較正」に、何も載せないときの生の値・重さの分かっている物を載せたときの値・その重さ (g) を入れると kg で表示されます。較正の値はデータフォルダの `weight_cal.json` に保存されます
   - データダウンロード: 選んでいる機器の全期間の記録を CSV で保存 (Excel で開ける形。重量は weight_kg の列も付く)
   - データクリア: 機器名とパスワードを入れると、その機器の記録・状態の履歴・メール送信履歴を消します。ファイルはデータフォルダの `cleared/<日時>/` に移るだけなので、戻せます

`ble.csv` には、末尾に `fence_state, fence_events, fence_blink_ago_s` の3列が増えます。既存のファイルは初回の受信で自動的に列が足されます。`kind` 列は電柵が `fa` です。

## 届くメール

| 件名 | いつ |
|---|---|
| 電柵の電圧が下がっています | 正常 → 電圧低下 |
| 電柵の電圧が一時的に下がりました | 記録と記録の間に下がって、もう戻っていたとき |
| 電柵の電圧が戻りました | 電圧低下 → 正常 |
| 電柵アラートの光センサが点灯したままです | 10秒以上光りっぱなし |
| HPX-F の電池を交換してください | 電池電圧が 2.6V 未満 |
| HPX-F から受信できていません | ハブは届いているのに、HPX-F の記録が1時間来ない |
| HPX-W の電池を交換してください | 電池電圧が 2.8V 未満 (センサページの「そろそろ交換」と同じ)、または電池の低下で測定を止めたとき。1回だけ ($HPX_W_BATT_V) |
| HPX-TH の電池を交換してください | 電池電圧が 2.7V 未満 (センサページの「交換」と同じ)。1回だけ ($HPX_TH_BATT_V) |
| HPX-W / HPX-TH / 温湿度計 から受信できていません | ハブは届いているのに、そのセンサの記録が24時間来ない ($HPX_SENSOR_MISSING_S)。ハブに登録中のセンサだけ |
| ハブ(…)から届いていません / 受信が戻りました | cron が、ハブからの受信が1時間ないことに気付いたとき / 戻ったとき |

## HPX-F の広告データ (16バイト)

| バイト | 内容 |
|---|---|
| 0–1 | 0xFF 0xFF |
| 2 | 'F' (v1.03 までは 'A') |
| 3 | 版 = 1 |
| 4–5 | 通し番号 |
| 6 | 状態 0=正常 1=電圧低下 2=常時点灯 |
| 7 | 直近60秒の点滅回数 |
| 8–9 | 電圧低下になった通算回数 |
| 10–11 | ノード内温度 ×100 |
| 12–13 | 最後の点滅からの秒数 (0xFFFF = 点滅なし) |
| 14–15 | 電池電圧 mV |

広告の名前は `HPXF` です (スキャン応答に入っています。v1.03 までは `HPX-alert`)。

## 4. 蜂場管理ページ (蜂場・巣箱・メモ・作業記録)

`hpx_site.php` (共通部分)、`apiary.php`、`hive.php`、`memo.php`、`work.php` を sensor.php と同じフォルダに置き、`https://<ドメイン>/hpx/apiary.php` を開きます。ログインはセンサページと共通 (アカウントごと) です。

- **蜂場** (`apiary.php`): 蜂場の登録 (名前・所在地・地図・地主・備考)。HPX-Core と電柵アラートセンサはここで蜂場に紐づける。蜂場ごとに巣箱の数、受信状況、タスク、最近のメモを表示
- **巣箱** (`hive.php`): 上のボタンで蜂場を切り替え。蜂場の HPX-Core (最終受信・ファーム・電池・Wi-Fi) と電柵の状態、巣箱ごとの情報・センサの今の値・温度/湿度/重量のグラフ (1日〜全期間、初めは3日)・タスク・最近のメモ。温湿度・重量センサは巣箱の「巣箱の情報を変更」で紐づける
- **メモ** (`memo.php`): 蜂場単位・巣箱単位のメモ。種類「内検」では女王・卵・王台・蜂の量・貯蜜も入れられる。蜂場・巣箱・種類・ことばで絞り込める
- **タスク** (`task.php`): これからの作業 (期限・タグ・担当者・メール・Googleカレンダー配信)。中身は work.php と共通
- **記録** (`work.php`): 済んだ作業の時間 (開始〜終了か分、人数)。月ごと・すべての合計を種類別に表示
- **リマインド**: 期限切れ・今日の タスクの数をメニューに表示。「メールで知らせる」にした タスクは、hpx_cron.php が毎朝 ($HPX_TODO_MAIL_HOUR 時、初期値7時) 期限の前日・当日・期限切れのものを1通にまとめて送る

登録した内容は、ログインしたアカウントのフォルダ `data/accounts/<ID>/site/` (site.json・memos.json・works.json) に保存されます (5. アカウント)。data/.htaccess で外からは開けません。

## 5. アカウント (ログイン・アカウントの発行) — 2026-10-26 追加

閲覧ページの共通パスワードをやめ、アカウントごとにログインする仕組みにしました。アカウントはサイト管理者が発行し、データ (蜂場・巣箱・メモ・作業記録・HPX-Core の記録) はアカウントごとに分かれます。前の版の PHP は `server_old_before_accounts/` に残してあります。

### 入れ替え手順 (今動いているサーバー)

1. **データフォルダ `www/hpx/data/` を丸ごとダウンロードしてバックアップする**
2. `server/` フォルダの**中身** (PHP と img/) を、さくらの今の `www/hpx/` に直接、上書きでアップロードする (server というフォルダは作らない。`data/` と `config.php` は上書きしない)。新しく増えたファイル: `hpx_auth.php` (共通)、`login.php` (ログイン・初期設定)、`account.php` (設定)、`admin.php` (管理)
   - `config.php` は上書きしなくて大丈夫です (足した項目は無くても動きます)。足すなら次の2行:
     - `$HPX_SITE_URL = '';` 招待メールに書くURLの元。空なら自動 (例 `'https://kotosan.sakura.ne.jp/hpx'`)
     - `$HPX_MAX_HUBS = 5;` 1アカウントにつなげる HPX-Core の台数 (0 = 無制限。サイト管理者は無制限)
3. `https://<ドメイン>/hpx/` を開くと「初期設定」が出る。今の共通パスワード (`$HPX_VIEW_PASSWORD`) を入れ、自分のメールアドレス・表示名・新しいパスワードを決める
   - これでサイト管理者のアカウントができ、`data/site/` と `data/<HPX-CoreのID>/` がそのアカウント (`data/accounts/<ID>/`) に移ります
   - `$HPX_TOKEN` はこのアカウントの機器用トークンになるので、**今の HPX-Core は設定を変えずにそのまま届きます**。`$HPX_MAIL_TO` は通知の送り先として引き継ぎます
4. 以後はメールアドレスとパスワードでログイン。`$HPX_VIEW_PASSWORD` は使わなくなります

うまくいかないときは、バックアップした data/ と `server_old_before_accounts/` の PHP を戻せば元通りです。

### 使い方

- **サーバー管理** (`admin.php`、サーバー管理者だけ。前の名前は「アカウント管理」): 「＋アカウントを発行」でメールアドレスと表示名を入れると招待メールが届き、本人がリンクを開いてパスワードを決めると使えるようになります。メールが届かないときのために、招待のリンクは画面にも出ます (72時間有効)。ほかに パスワード再設定のリンク、停止・再開 (停止中はログインもHPX-Coreの受信もできない)、権限の切り替え (「権限」の欄のプルダウンで サーバー管理者 / 一般アカウント)、削除 (停止してから。データは `data/deleted/` に残る)
- **設定** (`account.php`、全員): 表示名、パスワード、メールアドレス (=ログインID) の変更、通知メールの送り先、HPX-Core の接続
  - メールアドレスを変えると、新しいアドレスに確認メールが届き、リンクを開いた時点で切り替わります。記録はアカウントの内部ID で持っているので、そのまま引き継がれます
  - **HPX-Core を追加する人**: 設定ページの「送信先のURL」と「送信先のトークン」を HPX-Core の管理画面「動作設定」に入れる。最初の記録が届くとセンサページに出ます
- ログイン画面の「パスワードを忘れたとき」から、再設定のメールを送れます。同じメールアドレスで5回続けて間違えると15分ログインを止めます

## 6. チーム (同じ蜂場を複数人で管理) — 2026-10-26 追加

会社や同好会で、同じ蜂場を何人かで管理するための機能です。蜂場は今までどおり作った人 (持ち主) のアカウントにあり、それを**蜂場ごとに**チームへ共有します。前の版の PHP は `server_old_before_teams/` に残してあります。

### 入れ替え手順

1. `www/hpx/data/` をバックアップする
2. `server/` の PHP を上書きでアップロードする。新しく増えたファイル: `hpx_team.php` (共通)、`team.php` (チームページ)。変わったファイル: `hpx_auth.php`、`hpx_site.php`、`apiary.php`、`hive.php`、`memo.php`、`work.php`、`hpx_cron.php`、`admin.php`
3. `config.php` とデータはそのまま。チームを作るまでは、画面も動きも今までと同じです

うまくいかないときは、`server_old_before_teams/` の PHP を戻せば元通りです (チームの情報は `data/teams.json` と、蜂場の `share` 欄に入っているだけなので、残っていても前の版は気にしません)。

### 呼び名 (2026-10-28 TARO さん指定)

- **サーバー管理者** / **一般アカウント**: アカウントの区別 (サーバー管理ページを使えるか。前の呼び名はサイト管理者)。管理ページの「権限」の欄のプルダウンで切り替える

### 決めたこと (TARO さんと決定、2026-10-25)

- 1人がいくつのチームに入ってもよい
- 役割は **チーム管理者** と **メンバー** の2つ (閲覧だけの役割は無し)
- 共有は**蜂場ごと**。チームに共有した蜂場を、チームの全員に見せるか、選んだメンバーだけに見せるかを選べる (管理者はいつも見られる)
- 役割は**蜂場ごと**に決まる。同じ人が、ある蜂場ではメンバー、別の蜂場では管理者 (自分の蜂場なら持ち主) になってよい
- チームに蜂場を共有できるのは、そのチーム管理者でもある持ち主だけ。メンバーは自分のアカウントに蜂場を作れるが、チームには共有できない
- 新しい蜂場は、自分が管理者のチームの**全員に共有**するのが初期値 (蜂場を追加するときにチェックを外せば共有しない)

- **チーム** (`team.php`、上のメニューの右「チーム」): チームを作る (作った人が管理者)、メンバーをメールアドレスで追加 (アカウントがある人だけ。追加した人にメールで知らせる)、役割の変更、外す・抜ける (最後の管理者は抜けられない)、蜂場の共有と「見られる人」の設定、チームの削除

### 今回やっていないこと

## 8. デモ用アカウント (誰でも試せる) — 2026-10-28 追加

ウェブサイトから養蜂管理アプリ HPX-note を自由に試してもらうためのアカウントです (ログインなしで開ける。下の「ログインなしで開く」)。

デモ用アカウントでできないこと: 設定ページ (表示名・パスワード・メールアドレス・通知先・機器用トークン・カレンダー) の変更、チームの操作、センサページの操作、写真の追加 (写真以外の入力は保存されます)、管理ページ。メールも一切送りません (パスワード再設定・タスクのお知らせを含む)。ログインを続けて間違えても止めません。各ページの上に「デモ用アカウントです」と出ます。

使い方:
1. 管理ページでデモ用のメールアドレスのアカウントを発行し、パスワードを決めておく (今ある demo@… のアカウントをそのまま使える。中身もそのまま)
2. `config.php` に次を入れる
   ```php
   $HPX_DEMO_EMAIL = 'デモ用のメールアドレス';
   $HPX_DEMO_READONLY = false;    // true にすると見るだけ
   $HPX_DEMO_RESET_HOUR = 3;      // 毎日この時を過ぎた最初の hpx_cron.php で初期状態に戻す
   ```
3. 自分のアカウントで管理ページを開き、「デモ用アカウント」の「見本を直す (準備中にする)」を押す。準備中は、デモ用アカウントでも写真を追加でき、毎日の初期化も止まる
4. デモ用アカウントでログインして、見本の蜂場・巣箱・メモ・作業記録を入れる
5. 自分のアカウントの管理ページで「今の状態を初期状態として保存」を押す (data/demo_seed/ に保存され、準備中も終わる)
6. 以後、hpx_cron.php (15分ごとの定期実行) が毎日1回、初期状態に戻します。管理ページの「今すぐ初期状態に戻す」でもすぐ戻せます

見本を直したいときは、3〜5 をやり直してください。準備中の間は、ほかの人が同じアカウントで写真を追加することもできるので、なるべく短く済ませてください。
初期状態を保存するまでは戻しません。

**見本のセンサの記録と作業記録** (2026-10-29 追加): デモ用アカウントのセンサの記録は、実際のセンサの値を使わず、見本の値 (ダミー) で作ります。巣箱ごとに変化のパターンが違います (巣箱の並び順に「標準・強群・採蜜あり・弱群・給餌中・減少」を割り当て、7つめからは繰り返し)。1つめの巣箱は、温度 34℃±1℃ でほぼ一定、湿度は昼 60%・夜 90% くらいの日変動、重さは30日前の 30kg くらいから1日 0.3kg ずつ増え、昼は夜より 0.5kg 軽くなります。採蜜ありは8日前に 10kg 減り、弱群は重さが少しずつ減って温度が外気と一緒に上下し、給餌中は7日ごとに 1.8kg 増えます。温湿度計・重量センサが紐づいていない巣箱には、見本の HPX-Core (hpx-demo-2) のセンサを作って紐づけます (デモの蜂場データと初期状態の両方)。電柵アラートはずっと正常です。デモのページを開いたとき (5分に1回まで) と hpx_cron.php で、デモ用アカウントの HPX-Core ごとに直近30日分を作り直します (HPX-Core が無ければ見本の1台を作る)。デモ用アカウントのトークンで HPX-Core から届いた記録は保存しません (機器には「受け取った」と返す)。初めて見本の値にしたときに、それまでの実際の記録は HPX-Core のフォルダの ble_real_backup.csv に残します。作業記録 (記録ページ) には、架空のメンバー Aさん・Bさん・Cさん の12か月分の見本を足して見せます (保存はせず、変更・削除はできない)。止めるときは config.php に `$HPX_DEMO_DUMMY = false;` を書きます。

**ログインなしで開く**: `login.php?demo=1` を開くと、メールアドレスとパスワードを入れずにデモ用アカウントで開きます (ウェブサイトの「デモを試す」のリンク先にする。例 `https://hiveplusx.com/hpx/login.php?demo=1`)。ログイン画面にも「デモを開く」が出ます。ほかのアカウントでログイン中のときは、入れ替わる前に確かめます。なので、デモ用アカウントのパスワードは公開しなくてよい (誰にも教えない長いものにしておく)。

**HPX-Core をほかのアカウントに付け替えるとき**: HPX-Core のトークンを変えても、前のアカウントには記録が残り、「届いていません」のメールも出続けます。前のアカウントでセンサページを開き、いちばん下の「この HPX-Core をアカウントから外す」を押してください。メールが止まり、蜂場・巣箱の設定の選択肢からも消えますが、これまでの記録と巣箱・蜂場への紐づけは残るので、過去のグラフはそのまま見られます (センサページにも「外した」として残り、「元に戻す」もできます)。同じアカウントのトークンでまた届くと自動で元に戻ります。

**重量センサの較正の引き継ぎ**: 較正はセンサ (MAC) ごとの値なので、HPX-Core を別のアカウントに付け替えたり、センサを別の HPX-Core に移したりしたときは、ほかの HPX-Core のフォルダにある同じセンサの一番新しい較正 (差し引く重さも含む) を自動で写します。写したあとは、その HPX-Core の weight_cal.json に保存されます。

## 12. HPX-CAM (蜂場カメラ) の写真を見る — 2026-11-12 追加

HPX-CAM が撮った写真をサーバーに送り、HPX-note の「カメラ」ページで見ます (TARO さんの案、2026-11-12)。

### 送り道 (2026-11-12 TARO さん決定)

- **Wi-Fi・有線LAN の蜂場** (ルーターがある): HPX-CAM がルーター経由で **直接** サーバーへ送る

### 入れ替えるもの

| ファイル | 内容 |
|---|---|
| `server/hpx_cam.php` | カメラの共通部分 (保存の形・12時の写真を選ぶ・古い写真を消す・見られるカメラ) (新規) |
| `server/cam_upload.php` | 写真の受け口 (新規) |
| `server/camera.php` | カメラページ: 月の一覧 (各日12時の写真)・日付を指定して移動・1日の写真 (スライドバー・パラパラ再生)・カメラの設定 (新規) |
| `server/hpx_site.php`・`hpx_auth.php` | メニューに「カメラ」(写真が届いているときだけ。設定マークの中にはいつも) |
| `server/hive.php` | カメラの設定で選んだ巣箱のページに、そのカメラへのリンク (最新の写真の小さい版と時刻)。蜂場ページにはリンクを出さない (TARO さん指定)。巣箱ページから開いたカメラページは「← <巣箱> のページへ戻る」を出し、ほかのカメラへの切り替えは出さない (`camera.php?h=<巣箱id>`) |
| `server/config.sample.php` | `$HPX_MAX_CAMS` (台数の上限、初期 5)・`$HPX_CAM_KEEP_DAYS` (写真を残す日数、初期 365) |

`config.php` に2行が無くても初期値で動きます。

### 送り方 (ファームウェアを作るとき)

```
POST https://<ドメイン>/hpx/cam_upload.php?id=<カメラのID 12けた16進>&t=<撮影時刻 epoch秒>&bv=<電池V>&rssi=<dBm>[&core=<中継した HPX-CoreのID>]
Authorization: Bearer <機器用トークン (HPX-Core と同じ)>
Content-Type: image/jpeg
(本文は JPEG そのもの。1枚 2MB まで)
```

返事: `{"ok":true,"saved":1,"iv":10,"h0":5,"h1":19,"now":1794440505}`
- `iv` 撮影の間隔 (分)、`h0`〜`h1` 撮影する時間帯 (時)。カメラページの設定で変え、カメラは次の撮影から使う
- `now` はサーバーの時刻 (カメラの時計合わせ用)。`t` が7日より前・5分より先・無いときは、届いた時刻で保存する
- 同じカメラ・同じ撮影時刻の写真がもうあれば保存しない (`saved: 0`)。送りそこねたら同じ `t` で送り直してよい
- 1台1日 300枚まで。デモ用アカウントのトークンでは保存しない

### 保存先 (data/accounts/<アカウントID>/cams/<カメラのID>/)

- `cam.json`: 名前・置いている蜂場・最後に届いた時刻・電池・撮影の間隔と時間帯
- `<YYYYMMDD>/<HHMMSS>.jpg`: 写真そのまま、`<HHMMSS>_t.jpg`: 一覧用の小さい版 (長い辺 320px、GD で作る)
- `$HPX_CAM_KEEP_DAYS` より古い日のフォルダは、写真が届いたとき (1日1回) に消す
- 「このカメラを外す」は消さずに `cams_removed/` へ移す
- マイアカウントのバックアップ・全データのダウンロードには写真は入りません

### 容量と通信量の目安 (未実測)

| 画質 (1枚) | 10分ごと・昼14時間 (1日84枚) | 1か月 | 1年 |
|---|---|---|---|
| SVGA 800×600 (50〜80KB) | 約4〜7MB | 約130〜200MB | 約1.5〜2.5GB |
| UXGA 1600×1200 (150〜300KB) | 約13〜25MB | 約400〜750MB | 約5〜9GB |

### 写真が大きく変わったらお知らせ — 2026-11-13 追加

蜂場のメンバーにお知らせメール (LINE を連携した人は LINE) で送ります (`hpx_cam_watch.php`)。

1. **見くらべ (無料)**: 届いた写真を 32×24 の白黒に縮め、少し前 (90分以内) の写真と比べます。全体の明るさの違いはならしてから比べます。暗い写真 (夜・朝夕) は比べません
2. **AI で確認 (有料)**: 見くらべで大きく変わったときだけ、前と今の写真 (長い辺 800px) を AI (Claude) に見せ、
   「巣箱が倒れた・ずれた、人・動物がいる」などかを聞きます。明るさ・影・天気・草のゆれだけなら送りません。お知らせに AI の見立ても入ります
   - AI のキーが無いときは、2枚続けて変わったままのときに送ります (一時的な影・鳥では送らない。半分が雲の影になる、などでは送ることがあります)

設定 (`config.php`):

| 設定 | 初期値 | 意味 |
|---|---|---|

| `$HPX_CAM_QUIET_MIN` | 180 | 送ったあと、同じカメラではこの分数のあいだ送らない |

- カメラページの「⚙ このカメラの設定」で、カメラごとに 知らせない / 少なめ / ふつう / 多め を選べます (初期値 ふつう)
- 送ったものはカメラページの上に「⚠ カメラ画像に大きな変化がありました」として3日間出ます (押すとその写真へ)
- マイアカウントのお知らせメールに「カメラの変化」の種類を足しました (止められます)
- 料金の目安 (2026-11 の単価・1ドル150円、未実測): Haiku 5.5 で1回 約0.05円 (Sonnet 5.5 約1円)。1日10回聞いても1台 月 約15円
- 判定はカメラへの返事を返したあとに行うので、カメラを待たせません
- 試しの写真 (明るさ ±35%・半分が影・巣箱がひっくり返る・人くらいの大きさの影) で、明るさだけでは反応せず、ひっくり返りと人・半分の影で反応するのを確かめました。本物のカメラの写真ではまだ確かめていません

## 14. AIメモ・記録 (HPX-note の画面と LINE) — 2026-11-13 追加

話し言葉で書いた文を AI (Claude) が読み取り、メモ・作業記録にします。使う場所は2つあります。
- **HPX-note の画面「AIメモ・記録」** (`ai_note.php`。メニューに出る): 文を書く (🎤 音声入力も使える) →「AI で読み取る」→ 読み取った記録 (対象・日付・内容・作業の種類・時間・作業した人・人数・文) を確かめて直す → 「記録する」。記録には `via: "ai"` が付く
- **LINE** (下の説明): 送るとすぐ記録して LINE で返事をする。記録には `via: "line"` が付く

**タスク (これからやること) も入力できます** (2026-11-13 追加): 「来週の土曜までに山の蜂場に継箱を用意、鈴木さん担当」→ タスク (やること・期限・タグ・担当者。期限のお知らせメールはオン)。画面では期限・やること・タグ・担当者・お知らせを確かめて直せます。記録には `via` が付き、あとはタスクページのタスクと同じです。

どちらも「誰が・どんな作業を・何分」を読み取ります (例「鈴木さんと2人で給餌1時間」「Aさんが内検30分、Bさんが給餌1時間」→ 人ごとの作業記録)。作業した人に選べるのは、記録する蜂場を見られるチームの人だけ (チーム機能を使っていなければ持たない)。誰か言っていなければ記入者。AI を使える回数 `$HPX_AI_DAY_MAX` は画面と LINE の合計です。読み取りのしくみは `hpx_ai_note.php` にまとめてあります。

### 直した例から覚える
AI そのものは作り直しません (再学習はしない)。かわりに、本人が直した結果を2つの形で覚えて、次の読み取りで AI に渡します。書き方や巣箱・人の呼び方に、だんだん合ってきます。
- **覚えたこと (決まりの一覧)**: 直したところを、AI が「『いちばん』は 山の蜂場 / 1番 のこと」のような短い決まりにまとめてためる (アカウントの `ai_rules.json`、100件まで)。読み取るたびに**すべて**渡すので、古いまちがいもくり返しにくい。決まりにまとめるとき、直した回だけ AI をもう1回使う (利用料が少しかかる。回数の上限には数えない)
- **直した例**: 元の文・AI の読み取り・直した結果。覚えた例 (100件まで) の中から、**今回の文と似ている例**を6件まで (直したものを先に) 見本として渡す
- 例ができるとき: 画面で「記録する」を押したとき (AI の読み取りと違えば「直した」)、LINE で聞き返しに答えたとき。画面で「この結果は AI に覚えさせない」にチェックすれば残さない
- 例は本人の読み取りにだけ使う (チームのほかの人の文は AI に渡さない)。アカウントの `ai_learn.json` に新しい100件まで
- 「AIメモ・記録」ページの下の「AI が覚えたこと」で決まりを見る・直す・自分で足す・消す、「AI が覚えた例」で例を見る・消す
- 見本を渡す分、1回の利用料は少し上がる

### LINE で送ったメモ・作業記録を記録する

### 送り方 (例)
- 「山の蜂場の1番、女王いた、卵あり、王台なし、30分」→ 内検のメモ (+ 内検の作業記録 30分)
- 「きのう里の蜂場で給餌、糖液、1時間」→ 作業記録「給餌」(日付はきのう)
- 「2番の巣箱の前にスズメバチが10匹くらい」→ メモ「トラブル」
- 巣箱が分からないときは番号の一覧で、作業の時間が分からないときは「何分かかりましたか」と、LINE で聞き返す (30分以内に答える。「やめる」でやめる、「メモ」で時間なしのメモにする)
- 「取り消し」… LINE で最後に記録したものを消す (30分以内)。「使い方」… 送り方の例を返す
- LINE で書いた記録は、画面で書いたものと同じようにメモ・作業記録のページに出る (データには `via: "line"` が付く)。直すときは画面で直す

### 注意
- 返事は LINE の「応答 (reply)」なので、月200通の数には入らない。AI の読み取りに時間がかかって応答が間に合わなかったときだけ push で送る (これは1通に数えられる)
- AI に送るのは、送られた文と、その人の蜂場・巣箱の名前、作業の種類とタグの一覧だけ (センサの値やメールアドレスは送らない)
- AI の利用料は送った回数でかかる。`$HPX_AI_MODEL` が `claude-opus-5-5` (読み取りが正確) なら1回 数円くらい、`claude-haiku-5-5` にするとその数十分の1くらいの見込み (文の長さで変わる。実際の金額は Claude Console の Usage で確かめる)
- 養蜂の用語集 (内検・王台・給餌・分蜂・巣脾など約40語と、音声入力で化けやすい書き方「応対→王台」「休日→給餌」など) を AI に渡し、誤変換を直して読むようにしている。足したい言葉は `config.php` の `$HPX_AI_TERMS` に書く (例 `['キンリョウヘン' => ['金陵辺']]`)。蜂場・巣箱の名前は毎回その人の一覧を渡すので、登録しなくてよい
- 1人が1日に使える回数は `$HPX_AI_DAY_MAX` (初めは50回) まで
- 連携した人の文は記録に回るので、LINE公式アカウントのチャットで人が返事をしたいときは、その人にマイアカウントで「LINE で送った文を HPX-note に記録する」を外してもらう。連携していない人の文には、いままでどおり何もしない
- 記録のたびに `data/line_note.log` に1行残る (読み取れなかったときは `AI FAILED` と理由)。聞き返し中・取り消し用の情報は `data/line_note_state.json`、LINE の再送を見分ける情報は `data/line_events.json`
- デモ用アカウントは LINE を連携できないので、この機能も使えない

### 手書きの記録の写真から取り込む — 2026-11-14 追加

ノート・記録用紙・カレンダーなどに手で書いた記録を、写真に撮って取り込めます。AI (Claude) が写真の文字を読み、上と同じしくみで記録に分けます。手書きは読み違えやすいので、**どちらも確かめてから記録します** (すぐには記録しない)。

- **LINE**: トークに写真を送る → 「写真から読み取った文」「読みにくかった所」「記録する内容」が返ってくる → 合っていれば「OK」、違うところは文で送る (例「3番ではなく5番」「王台はなし」。読み直してもう一度見せる)、「やめる」でやめる。60分以内に答える。巣箱や時間が分からないときは、OK の後でいつものように聞き返す
- **画面**: 「AIメモ・記録」の「📷 手書きの記録の写真から」で写真を選ぶ → 写真の文字が文の欄に入る → 直してから「AI で読み取る」。LINE の返事にある「画面でくわしく直す」のリンク (`ai_note.php?photo=line`) から、LINE で送った写真の文を画面で直すこともできる (24時間以内)
- 読みにくい所は、文の中で `〔王台?〕` のように印を付け、一覧にする (ほかに考えられる読み・どこに書いてあったか)。写真と見くらべて直す
- 記録したメモには、元の写真を付ける (メモの写真と同じ。画面ではチェックを外せば付けない)。「取り消し」でメモを消すと写真も消える
- 写真はアカウントの `ai_photo.jpg` に1枚だけ置き (長い辺 1568px)、記録した・やめたら消す。読み取った文は `ai_photo.json`
- AI は2回使う (文字を読む + 記録に分ける)。回数の上限には1回と数える。文字を読むときは少しよく考えさせる設定 (effort medium) なので、1回の利用料は文より高く、返事まで数十秒かかることがある (間に合わないと push で返事 = 月の通数に1通数えられる)
- AI に送るのは、写真と、その人の蜂場・巣箱の名前・作業の種類・用語集だけ
- 入れ替えるもの: `hpx_ai_note.php`・`hpx_line_note.php`・`line_webhook.php`・`hpx_line.php`・`ai_note.php`。config の追加は無い

## 15. AI の教師データ用の記録 — 2026-11-13 追加

将来、巣箱の異常やスズメバチをセンサとカメラから見分ける AI を作るときに、あとから取り戻せないデータを今のうちに残すしくみ。

### 機器と巣箱のつながりの履歴 (`server/hpx_links.php`)

- 蜂場・巣箱の設定 (`site.json`) とカメラの設定 (`cam.json`) には「今」のつながりしか無いので、つながりが変わるたびにアカウントの `site/links.json` に書き足す
- 書くもの: 温湿度・重量センサ → 巣箱 (`s:`)、電柵アラートセンサ → 蜂場 (`f:`)、HPX-Core → 蜂場 (`core:`)、巣箱 → 蜂場 (`hv:`)、HPX-CAM → 巣箱か蜂場 (`cam:`)。外したときは `to` が空
- 蜂場・巣箱を保存したとき、カメラの設定を保存したとき、`hpx_cron.php` の毎回の実行で見くらべる (変わっていなければ書かない)。最初の1回は今のつながりを `first: 1` で書く (いつからかは分からない)
- `site/` にあるので、バックアップ・全アカウントのデータのダウンロードにそのまま入る。デモ用アカウントは残さない

### データのダウンロードを促すお知らせ (`server/hpx_dl_remind.php`)

サーバーに古いデータを置き続けない代わりに、手元に保存してもらう (カメラの写真は `$HPX_CAM_KEEP_DAYS` 日で消える)。

| 相手 | いつ | どこに |
|---|---|---|
| サーバー管理者 | 全アカウントのデータを `$HPX_EXPORT_REMIND_DAYS` 日 (初期30日) ダウンロードしていない | 画面の上 + メール (その日数ごとに1回) |
| 利用者 | 自分のデータ (バックアップ・データ一括ダウンロード・カメラの1か月分) を `$HPX_USER_DL_REMIND_DAYS` 日 (初期90日) ダウンロードしていない | 画面の上 (「あとで」で30日だまる) |

- 0 にすると出さない。いつダウンロードしたかは `users.json` の `dl_last` と、データフォルダの `export_all_last.json`
- カメラのページの月の一覧の下に「この月の写真をまとめて保存 (ZIP)」(見られる人ならだれでも)
- 全アカウントのデータの「HPX-CAM の写真」: 入れない / 前回入れた日から / すべて。とても大きくなるので「前回入れた日から」で少しずつ保存する

### メモの時刻と共通の出来事

- メモに時刻 (分かれば) を書けるようにした (`memos.json` の `time`、HH:MM)。AIメモ・記録でも、出来事の時刻が分かれば入れる
- メモのタグの先頭に「共通の出来事」 スズメバチ・分蜂・逃去・盗蜂・大量死・入居・クマ (`hpx_site.php` の `S_MEMO_EVENTS`) をいつも出し、カスタマイズで消せないようにした。だれのメモでも同じ言葉になり、AI の答え (ラベル) として集計しやすい

### 開花の記録 — 2026-11-13 追加

- メモの内容を「開花植物」にすると、植物・咲き具合 (つぼみ・咲き始め・満開・終わり・不明)・ミツバチの訪花 (多い・ふつう・少ない・見ない・不明。「-」は書いていない、「不明」は見たが分からない) を選べる (`memos.json` の `flower`)
- 植物は重要な蜜源だけ一覧から選ぶ (`hpx_site.php` の `S_FLOWER_PLANTS`、約20種)。一覧に無いものは「一覧に無い (書く)」で名前を書き、「次から一覧で選べるようにする」でその人の一覧 (`site/flower_plants.json`) に足す。足した植物はフォームの「自分で足した植物を一覧から外す」で外せる
- データ一括ダウンロードのメモ.csv に「開花 植物・咲き具合・ミツバチの訪花」の列。AIメモ・記録でも読み取る
